# Delta Media Recode (V2)

Полная переработка портала Delta Media на Go Fiber: чистая архитектура,
файлы по 100–200 строк, серверная валидация всех форм и новые системы
(коды аккаунтов, 2FA через Telegram с GPS, недельные выплаты, CryptoBot).

## Что внутри

| Блок | Описание |
|---|---|
| **Вход по коду** | Кнопка «Войти» справа в хедере. Код вида `DLT-XXXXX-XXXXX`, 1 код = 1 аккаунт (роль: admin / moderator / media / freemedia). Коды выпускаются только в админ-панели. |
| **2FA + GPS** | После кода браузер запрашивает геолокацию (обязательно), в Telegram приходит IP + координаты с картой и кнопками «✅ Подтвердить / 🚫 Это не я». Сессия — httpOnly cookie. |
| **Публичная заявка на медиа** | Форма вступления в медиа (UID, критерии, YT/TT, серверы, капча Turnstile, проверка «написал сотруднику»). |
| **Кабинет модератора** | Сброс HWID и Discord-баны с чанковыми загрузками доказательств (до `MAX_UPLOAD_GB`). |
| **Кабинет медиа** | Заявки на выплату за снятые видео (USDT-чек / FunPay) и на лоты (YT/TT/FunPay → ссылка на лот). |
| **Кабинет фримедиа** | Запрос подписки. |
| **Недельный цикл выплат** | Приём вт 01:00 → пн 22:00 (МСК, `WEEK_TZ`). Таблица «Медиа выплаты» в админке: недели архивируются в БД с меткой «неделя с ДД.ММ.ГГ до ДД.ММ.ГГ», редактируемый итоговый текст недели, недельный отчёт владельцам в TG. |
| **Пасты выплат в Telegram** | Заявку можно подать пастей боту. Принимаются только от активных аккаунтов медиа (это и есть «папка медиа выплаты» — посторонние пасты игнорируются), шаблон редактируется в админке. |
| **Автовыплаты USDT** | CryptoBot Pay API: `Принять` → перевод `{amount} USDT` получателю по spend-id выплаты. Токен в `CRYPTOBOT_API_TOKEN`. FunPay-выплаты — текст по шаблону. Отклонение — паста с причиной с сайта. |
| **Telegram-секретарь** | Business API: автоответ GIF-стикером с задержкой 15–180 с, прочтение за 10 с до ответа. |
| **24h-окна** | Напоминание юзеру за 5 минут до истечения окна ответов; в админке — live-статусы окон. |
| **Заявки в Telegram** | Админ получает полные заявки с кнопками «✅/❌» прямо в TG. |
| **Банлист** | IP (включая CIDR-подсети), ссылки YouTube/TikTok, Telegram-юзеры, UID. Проверяется при каждой подаче. |
| **Админка** | Новые заявки внизу таблицы, глобальные фильтры на все таблицы, журнал (live), редактор текстов/паст. |

## Запуск

```bash
cp .env.example .env   # заполнить секреты
go build -ldflags="-s -w" -o delta-media-recode.exe .
./delta-media-recode.exe
```

- Первый аккаунт администратора создаётся автоматически из `ADMIN_BOOTSTRAP_CODE`.
- Чтобы 2FA доходили, владелец должен написать боту `/start` (бот запоминает Telegram ID).
- `DB_DRIVER=sqlite` для разработки, `postgres` — Supabase (прод). Схема `v2_*` не конфликтует со старыми таблицами.

## Структура

```
main.go                    # маршруты и связки сервисов
config/                    # .env
internal/
  database/                # подключение, миграции v2_*, настройки
  models/                  # доменные модели (по файлу на агрегат)
  validation/              # вся серверная валидация текстов
  auth/                    # коды, 2FA-попытки, сессии, middleware
  bans/                    # банлист с in-memory кэшем (IP/CIDR + ссылки + UID)
  telegram/                # бот, секретарь, 2FA, пасты, окна, CryptoBot
  payouts/                 # недельный цикл, заявки, отчёты
  handlers/                # HTTP: public, mod, cabinet, admin_*
  uploads/                 # чанковые загрузки
  middleware/              # real IP, IP-ban, rate limit, аудит
web/                       # SPA: index.html + css + js (по модулю на файл)
tools/e2e                  # сквозной тест локального сервера
```

## Отличия от V1 (исправлено)

- Бан по IP работает на всех маршрутах и поддерживает подсети.
- Глобальные фильтры админки применяются ко всем таблицам; новые заявки внизу.
- Live-поллинг журнала больше не «мёртв» (была ошибка guard-селектора).
- Модераторские ключи `DELTA-...` заменены едиными кодами аккаунтов с 2FA.
- Вся валидация текстов дублируется на сервере; XSS-безопасный вывод.
- Секрет `.env` не коммитится; тестовый мусор не засеивается в прод-БД.
