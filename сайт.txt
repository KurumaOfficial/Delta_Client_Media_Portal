# ТЗ НА САЙТ FREE MEDIA DELTA CLIENT

## 1. Общая информация

Необходимо разработать простой современный сайт для подачи различных заявок, связанных с Free Media Delta Client.

Проект должен быть реализован с использованием:

* HTML — структура сайта;
* CSS — дизайн и адаптивность;
* JavaScript — вся интерактивная логика.

На первом этапе сайт может работать как frontend-прототип без настоящей базы данных и отправки заявок на сервер.

Сайт должен иметь тёмную тематику, минималистичный дизайн и быть удобным как на компьютере, так и на телефоне.

---

# 2. Основные разделы сайта

В верхней части сайта по центру расположена панель вкладок.

Обычный пользователь должен видеть только:

1. Заявка на медиа

Вкладки для модераторов:

2. Сброс HWID
3. Discord баны

Вкладка для администратора должна быть доступна только после специального секретного действия и не должна отображаться обычному пользователю.

---

# 3. Главная вкладка — «Заявка на медиа»

Это единственная вкладка, которая доступна всем пользователям.

В начале страницы должен находиться заголовок:

«Заявка на медиа»

Под заголовком можно разместить небольшое описание:

«Заполните форму ниже для вступления в Free Media Delta Client. Перед отправкой внимательно проверьте все указанные данные.»

# 4. Вопрос №1 — соответствие критериям

Вопрос:

«Подходите ли вы по критериям?»

Варианты:

* Да
* Нет

Варианты должны быть оформлены красиво, например в виде двух кнопок/плашек.

Ниже должен находиться текст:

«Актуальные критерии для вступления в медиа можно посмотреть здесь.»

Слово «здесь» должно быть кликабельным.

После нажатия должно открываться модальное окно с критериями.

Модальное окно должно иметь:

* заголовок «Критерии медиа»;
* список актуальных критериев;
* кнопку закрытия «×»;
* возможность закрыть окно нажатием вне самого окна.

Критерии должны быть вынесены в отдельный блок, чтобы их можно было легко изменить в будущем.

# 8. Отправка заявки на медиа

Внизу формы должна находиться большая кнопка:

«Отправить заявку»

Перед отправкой JavaScript должен проверить абсолютно все обязательные поля.

Если хотя бы одно поле не заполнено:

кнопка становится красной и меняет текст на:

«Ошибка! Заполните все пункты»

ВАЖНО:

При ошибке содержимое формы НЕ должно очищаться.

Пользователь должен сохранить всё, что уже написал, и просто заполнить недостающий пункт.

Через 3 секунды после появления ошибки кнопка должна автоматически вернуться в первоначальное состояние:

«Отправить заявку»

и вернуть обычный цвет.

То есть ошибка должна исчезать автоматически через 3 секунды.

---

# 9. Успешная отправка заявки

Если все необходимые поля заполнены, считается, что заявка успешно отправлена.

После успешной отправки:

1. Все поля формы очищаются.
2. Выбранная платформа сбрасывается.
3. Выбранные серверы сбрасываются.
4. Дополнительные вопросы YouTube/TikTok скрываются.
5. Кнопка становится зелёной.
6. Текст кнопки меняется на:

«Заявка успешно отправлена!»

Сообщение об успешной отправке должно отображаться примерно 3 секунды.

После этого кнопка возвращается в обычное состояние:

«Отправить заявку»

# 10. Скрытые вкладки для модераторов

Обычный пользователь не должен видеть вкладки:

* Сброс HWID
* Discord баны

Они должны быть полностью скрыты при обычном открытии сайта.

Необходимо сделать секретное действие для входа в режим модератора.

Например:

Ctrl + M

После этого появляется небольшое модальное окно:

«Вход для модератора»

В окне:

* поле для секретного кода;
* кнопка «Войти»;
* кнопка закрытия.

Если код правильный, включается режим модератора.

После включения режима:

* появляется вкладка «Сброс HWID»;
* появляется вкладка «Discord баны»;
* обычная вкладка «Заявка на медиа» остаётся доступной.

Если код неправильный:

показывается сообщение:

«Неверный код»

При этом модераторские вкладки не появляются.

---

# 11. Важно про безопасность модераторов

Если проект на данном этапе состоит только из HTML + CSS + JS, секретный код нельзя считать настоящей защитой.

Код, находящийся внутри JavaScript, технически можно посмотреть через исходный код сайта.

Поэтому на этапе frontend это должно рассматриваться только как визуальное скрытие вкладок.

В дальнейшем, если сайт будет использоваться в реальной работе, необходимо перенести авторизацию на backend.

Сайт должен нормально работать на:

* ноутбуке;
* планшете;
* телефоне.

На маленьком экране:

* вкладки могут переноситься;
* карточки занимают почти всю ширину;
* поля ввода остаются удобными;
* кнопки должны быть достаточно большими для нажатия пальцем.

---

# 27. Валидация

JavaScript должен проверять все обязательные поля.

Проверять:

* пустые строки;
* dropdown без выбранного значения;
* отсутствие выбранных серверов;
* отсутствие доказательства;
* отсутствие ссылки/файла;
* отсутствие ответа на обязательные вопросы.

Для доказательств логика:

«Файл ИЛИ ссылка»

То есть:

файл есть → всё хорошо;

ссылка есть → всё хорошо;

файла нет + ссылки нет → ошибка.

---

# 28. Главное правило при ошибке

Это особенно важно.

При ошибке форма НЕ должна сбрасываться.

Например пользователь заполнил:

* UUID;
* причину;
* ссылку на доказательство;

но забыл что-то ещё.

После нажатия:

«Ошибка! Заполните все пункты»

Все введённые данные должны остаться.

Через 3 секунды сообщение об ошибке исчезает, а пользователь продолжает заполнение формы.

---

# 29. Главное правило при успешной отправке

При успешной отправке форма очищается полностью.

После очистки:

* input очищаются;
* textarea очищаются;
* dropdown сбрасываются;
* выбранные checkbox снимаются;
* выбранная платформа сбрасывается;
* дополнительные вопросы скрываются.

---

# 30. Структура проекта

Желательно разделить проект минимум на:

* index.html
* style.css
* script.js

HTML отвечает только за структуру.

CSS отвечает только за внешний вид.

JavaScript отвечает за:

* переключение вкладок;
* dropdown;
* мультивыбор серверов;
* модальные окна;
* проверку форм;
* ошибки;
* успешную отправку;
* скрытый режим модератора;
* скрытый режим администратора.

Не желательно помещать весь CSS и JavaScript непосредственно внутрь HTML, если проект уже будет развиваться.

---

# 31. Будущая серверная часть

В будущем необходимо добавить backend.

Он должен отвечать за:

* настоящую отправку заявок;
* хранение заявок;
* авторизацию модераторов;
* авторизацию администратора;
* хранение загруженных доказательств;
* просмотр заявок;
* статусы заявок;
* защиту секретных кодов.

После добавления backend секретные коды нельзя хранить непосредственно в JavaScript на стороне клиента.

---

# 32. Важное уточнение по текущей версии

На этапе HTML + CSS + JS кнопка «Заявка успешно отправлена!» означает только успешное прохождение локальной проверки формы.

Она ещё не означает, что заявка реально отправилась модератору.

Для настоящей отправки потребуется backend/API.

В будущем можно подключить, например, Discord Webhook или собственный сервер, чтобы после отправки информация автоматически приходила в нужный Discord-канал.

---

# 33. Итоговая логика доступа

### Обычный пользователь

Видит:

**Заявка на медиа**

Не видит:

**Сброс HWID**

**Discord баны**

**Панель администратора**

---

### Модератор

После секретного сочетания клавиш + правильного кода получает:

**Заявка на медиа**

**Сброс HWID**

**Discord баны**

---

### Администратор

После отдельного секретного сочетания клавиш + правильного кода получает:

**Панель администратора**

При этом администраторская панель должна быть отдельной от обычных пользовательских вкладок.

---

# 34. Итог

Главная задача проекта — сделать удобную единую форму для трёх типов заявок:

**Медиа → HWID → Discord Ban**

При этом:

* медиа доступно всем;
* HWID доступен только модераторам;
* Discord Ban доступен только модераторам;
* административная панель доступна только администратору;
* доступ модератора и администратора осуществляется через секретное сочетание клавиш;
* все формы имеют обязательную валидацию;
* при ошибке данные сохраняются;
* ошибка исчезает через **3 секунды**;
* при успехе форма очищается;
* успешное сообщение исчезает через **3 секунды**;
* серверы выбираются через красивый мульти-dropdown с галочками;
* выбранные серверы отображаются непосредственно в строке dropdown;
* доказательства можно предоставить файлом или ссылкой;
* дизайн единый, тёмный, современный и адаптивный.
